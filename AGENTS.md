# Product and design requirements

Read docs/design.md before changing any interface. The user explicitly requires Notion and Linear as enduring quality references. Apply their principles to working interactions, hierarchy, consistency and speed; do not settle for a static dashboard or cosmetic resemblance.

Preserve functional evidence inspection, server-validated decisions and exports. Keep model suggestions, deterministic results and human decisions visibly distinct. Never present unimplemented controls or fabricated metrics as functional features.

For interface changes, run the browser workflow checks, inspect actual screenshots at desktop/mobile sizes, and test keyboard navigation and failure states relevant to the change. Avoid hiding essential controls behind hover or shortcuts alone. Update the documented implemented/remaining boundary. No subagents are required.
