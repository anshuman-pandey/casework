## Apply a prepared PR

Fork the relevant upstream repo with a GitHub account that has permission, clone the fork, create a branch, and run `git apply /absolute/path/to/the.patch`. Review against the latest upstream version. For the SaaS alternatives repo, run `node scripts/validate.mjs` and `node scripts/build-readme.mjs`; do not edit its generated README manually. The supplied patch was generated with both commands. No unrelated entries are changed.

For the SaaS alternatives list, its [issue form](https://github.com/Anil-matcha/awesome-open-source-saas-alternatives/issues/new?template=add-alternative.yml) is the easier supported route: paste the fields from the prepared issue body. Its automation creates a PR for maintainer review. Do not submit both an issue and a direct PR for the same entry.

Each proposal discloses maintainer affiliation and the synthetic-data preview boundary. No AI resolution, regulatory certification, enterprise readiness or incumbent feature parity is claimed. Track the returned issue/PR URL and actual maintainer decision here when submitted. No payment, affiliate link, or paid promotion is included.
